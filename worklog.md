Agent: main (Z.ai)
Task: Diagnose and fix "app not working" — dead dev server + two streaming-engine defects (live-radio infinite stall, silent mid-stream pump death).

Work Log:
- Root cause 0 (environment): the sandbox was reset — node_modules was missing and no dev server was running, so the app loaded nowhere. Fixed via npm install + setsid-persisted `vite --host 0.0.0.0 --port 5173` (200 OK, stable).
- Root cause 1 (live-radio freeze, the user-visible bug): MseStream.fetchAndAppendChunk used `res.blob()` on the stream response. Live radio bodies never end, so blob() never resolves → start() awaited forever → load() never completed → no native fallback, no error — player frozen at "Buffering"/LIVE with readyState 0 (verified live: engine src=blob, t=0 forever). Radio hosts also ignore Range (always 200) and omit Range from CORS allow-headers.
- Root cause 2 (mid-stream stall): on a mid-file chunk failure the pump returned false WITHOUT fail() (paths: !res.ok, aborted) → silent pump death → eternal "Buffering" at e.g. 38s with mseActive still true (observed on an Audius track).
- Rewrote src/lib/mseStream.ts: (a) 12s header deadline + 20s bounded-body deadline on every fetch; (b) readBounded capped reader replaces res.blob() everywhere; (c) Range-first strategy — 206 hosts keep the old paced 256KB window streaming; if the Range request dies before any response on the first chunk (live-radio preflight/host signature), one no-Range retry turns the same request into a CORS simple request and streams that 200 body PROGRESSIVELY in 32KB windows (works for endless live bodies and finite files alike; start() resolves after the first window); (d) every pump break now ends in finish() (EOF), fail() (native fallback preserving playhead), or one 800ms transparent retry then fail() — no silent stalls possible; (e) mid-stream 200 (server stopped honoring Range) → fail() instead of silent break; (f) progressive reconnect distinguishes EOF (content-length known + reached → endOfStream) from cut connections (one reconnect, then native fallback); (g) reader cleanup in stop()/fail().
- Hardened src/hooks/useAudioEngine.ts load(): candidate.start() raced against a 12s guard; guard loss → candidate.stop() + native path. Guard timer cleared when start() wins (no stray kill of healthy streams). load() can no longer hang on any source.
- Verified live (agent-browser): radio "Спокойное радио" (myradio24) now PLAYS via progressive MSE (t advances 8.8s+, readyState 4, single clean fetch); Audius restored to paced 206 Range chunks (sequential bytes=0-262143→262144…, ~700ms cadence, mseActive true, t advancing); zero console/page errors. Interim regression caught and fixed during verification: initial no-Range-first design made Audius serve whole files (200) into RAM — replaced by Range-first + failover-to-no-Range.
- npx tsc -b --noEmit clean; 129/129 tests pass; production build clean (~116KB gzip core, route-split unchanged).
